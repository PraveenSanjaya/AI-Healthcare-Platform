| 27 | 2026-11-05 | `POST /api/generate` streams **NDJSON** (one JSON object per line: `text`, then `done` with the saved ids, or `error`), not SSE. | 28 | 2026-11-05 | The route is a thin wrapper over `lib/ai/handler.ts`, which takes its dependencies (repos, provider, audit, clock) as arguments. | 29 | 2026-11-05 | PHI policy on the server: findings on any input (and on a refinement instruction) return 422 and write `PHI_BLOCKED`. An ADMIN may send `override: {reason}` (10-500 characters) and gets `PHI_OVERRIDE` with the reason; anyone else sending an override gets 403 and `PHI_BLOCKED`. **Audit metadata holds field names, types and counts, never the matched text.** | Spec Phase 5. The audit log must not become a second copy of the PHI. |
| 30 | 2026-11-05 | Rate limit: a sliding one-hour window over the user's saved Generations plus GenerationRefinements, `RATE_LIMIT_PER_HOUR` (default 30; invalid values fall back to 30), applies to every role, returns 429 with `Retry-After`. Failed generations are not saved and so do not count. | Needs no extra table. Known gap: concurrent requests can slightly exceed the limit because the count is read before the save. |
| 31 | 2026-11-05 | Refining a draft clears `reviewed`/`reviewedAt` on the Generation, because the text changed; the user must tick "I have reviewed this" again. | 32 | 2026-11-05 | The Copy gate for PATIENT_FACING drafts is enforced in the UI only; the server records the review but cannot stop a browser copying text it already shows. INTERNAL drafts copy freely. | A clipboard cannot be guarded server-side; the review and its audit entry are the control. |
